# 技术路线与代码核对

## 为什么没有直接用 YOLO 棋子检测

YOLO 检测可以一次找出多枚棋子，但还要把每个框映射到 10×9 交叉点，并处理漏框、重框和相邻框冲突。第 4 课已经把棋盘归一化成固定俯视图，因此这里直接利用棋盘的固定结构，让模型一次输出 90 个位置的分类分数。

| 路线 | 优点 | 本任务的额外代价 |
| --- | --- | --- |
| YOLO 检测 | 适合一般多目标检测 | 检测框还要映射到棋盘交叉点 |
| OCR | 看似可直接识别汉字 | 字体、旋转、反光、磨损变化大 |
| 单格分类 | 容易理解 | 90 次推理，丢失整盘上下文 |
| 整盘多区域分类 | 一次得到固定 90 个位置 | 依赖第 4 课的拉正质量 |

## 视频与代码一致性

| 视频表达 | 代码位置 |
| --- | --- |
| 整张棋盘只推理一次 | `BoardClassifier.predict()` 只调用一次 `session.run()` |
| 输出必须是 90×16 | 代码强校验 `outputs[0].shape[1:] == (90, 16)` |
| 每个位置取最高分 | `np.argmax(logits, axis=1)` |
| 还原成棋子表 | `layout_to_board()` 生成 `piece + row/col` |
| 识别结果需要质量检查 | 红帅、黑将数量和棋子上限检查 |

视频中的置信度数字用于解释 `argmax`，不冒充某张真实照片的实测分数。
